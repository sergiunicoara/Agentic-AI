S04

Live config switch: Redis → SQLite fallback

ShotTerminal only — the "how does it not break in prod" beat. Let the before/after /health calls sit for a beat each.

bash — recruiter-agent
curl -s localhost:9191/health
{"session_store": {"backend": "sqlite", "redis_url_set": false}}

kill %1; REDIS_URL=redis://localhost:6379/0 python -m app.server &
sleep 2 && curl -s localhost:9191/health
{"session_store": {"backend": "redis", "redis_url_set": true}}
V.O.
Same binary, same code path — set REDIS_URL and session state moves to Redis with a 24-hour TTL. Drop the env var, or let the connection fail, and it falls back to SQLite silently, logged at WARNING. No restart-time branch, no feature flag — it's a runtime probe in session_store.py.
noteIf no local Redis is running for the recording, skip the second half and narrate the fallback from the code instead — don't fake a connection succeeding.

V.O.
Fifteen golden recruiter conversations, replayed against the live agent every run. Gemini 2.5 Flash judges each reply on faithfulness, relevancy, and factuality, with a rubric that knows the agent's correct behaviors — sharing CV facts isn't a privacy violation here, it's the job. Pass threshold is 3.5 out of 5. Any regression against this file blocks deploy in CI.

S08

The tests that caught real bugs

ShotTerminal. A fully green suite — the V.O. tells the story of how it got green, which builds more trust than the checkmarks.

bash — recruiter-agent
python -m pytest tests/ -q
............                                               [100%]
12 passed, 8 warnings in 49s
V.O.
Twelve for twelve — but the interesting part is how it got there. Seven tests cover barge-in; writing them caught a real race where an already-synthesized sentence could get dropped mid-interrupt. And two tests used to fail — chasing them exposed a routing bug where every GET endpoint, health check included, silently returned the web page instead of JSON.
noteThe old failing tests weren't deleted to make the suite green — they were chased to the real bug (a route-ordering issue in server.py), fixed, and replaced with regression tests that guard against it coming back.
